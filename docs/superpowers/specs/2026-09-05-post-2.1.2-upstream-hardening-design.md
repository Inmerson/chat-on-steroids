# Post-2.1.2 Upstream Hardening Without Regressing Fork Architecture

Date: 2026-09-05

## Purpose

Bring the remaining useful upstream hardening into the Inmerson 2.1.2 line without merging upstream history or weakening Agent System 3.0, Control Center, autonomous execution, Infinite Loop/scoped recovery, worker lifecycle, terminal continuation, updater, privacy, sandbox, or the Windows-only Desktop boundary.

## Protected reference

- Fork reference: `origin/main` at `4b70f3d` (`v2.1.2`).
- Upstream reference: `upstream/main` at `62608f2`.
- Integration style: fork-native selective ports only. No merge, rebase, blind cherry-pick, reset, or force-push.
- Production behavior uses TDD: a deterministic regression must fail against the fork baseline before implementation.
- Version files remain unchanged.

## Candidate classification

### 1. ChatGPT Project conversation routes — SAFE_MANUAL_PORT

The extension recognizes ordinary `/c/<conversation>` routes but its service-worker URL parser still misses `/g/<project>/c/<conversation>`. This can break the earliest browser identity boundary before attribution, session recording, recovery, and worker routing consume the conversation id.

Required behavior:

- Accept exactly `/c/<id>` and `/g/<project-slug>/c/<id>` on supported ChatGPT hosts.
- Reject public/share lookalikes such as `/share/c/<id>`.
- Use the same route grammar in DOM/content and service-worker parsing.
- Preserve navigation-epoch and exact-conversation guards.

### 2. Browser tab/window keyboard chord protection — SAFE_MANUAL_PORT

Upstream introduced a pure browser-chord classifier to prevent Desktop automation from closing, switching, creating, or navigating browser tabs/windows through blind keyboard shortcuts. The fork does not have this guard.

Required behavior:

- Recognize Chrome-family/Firefox/Safari/Arc browser process names.
- Refuse browser-owned tab/window/address-bar chords such as Ctrl/Cmd+W, Ctrl/Cmd+Tab, Ctrl/Cmd+1..9, Ctrl/Cmd+L, new-window/new-tab and browser history chords.
- Leave page-level keys such as copy/paste/save/reload to existing Desktop behavior unless separately prohibited.
- Apply the refusal only when the target window is a browser.
- Do not introduce macOS Desktop discovery; the helper is host-agnostic testable logic but the live Desktop connector remains Windows-only.

### 3. Windows swapped primary/secondary mouse buttons — SAFE_MANUAL_PORT

Windows `SendInput` flags name physical buttons while users can configure primary/secondary semantics with `SM_SWAPBUTTON`. The fork currently chooses physical left/right flags without consulting that setting.

Required behavior:

- Read `GetSystemMetrics(SM_SWAPBUTTON)` per click/drag decision.
- Map caller `left` to the user's primary button and caller `right` to secondary.
- Keep middle/wheel unchanged.
- Cover click, double-click, drag and semantic-ref fallback through the shared button mapping.

### 4. Preserve unread background exec results — SAFE_MANUAL_PORT

The current manager drains output correctly, but a proven conversation can keep starting commands while completed retained sessions still owe unread output. Under pressure, that makes finished results easier to strand and turns global capacity into the first feedback mechanism.

Required behavior:

- Treat retained exited sessions as unread obligations until `write_stdin` drains/releases them.
- Expose a non-destructive background state projection for process ids owned by a proven conversation.
- Refuse a new `exec_command` for a proven conversation once four exited unread results are waiting; spawn nothing on refusal.
- Return the exact waiting session ids and instruct the caller to drain them with `write_stdin`.
- Append bounded same-conversation reminders about finished unread sessions to later tool results without consuming output.
- Preserve authenticated cross-chat/unattributed terminal continuation: conversation ownership remains attribution/routing metadata, not an authorization boundary.
- Keep global process capacity as admission, never garbage-collection of unread output.

### 5. Precise tool outcome taxonomy and background completion notices — SAFE_MANUAL_PORT

The fork currently records `ok | rejected | error`, which conflates child-process non-zero exits, expected tool refusals, and connector defects. Upstream separates these outcomes and uses finished background-session reminders.

Required behavior:

- New canonical outcomes: `ok`, `process_exit_nonzero`, `tool_rejected`, `tool_internal_error`.
- Preserve read compatibility for legacy `rejected` and self-proving legacy exec `error` rows.
- A non-zero command exit is a reported process result, not automatically a connector defect.
- Expected permission/schema/tool refusals record `tool_rejected`.
- Unexpected connector/runtime failures record `tool_internal_error`.
- Outcome severity can only become more specific; generic wrappers cannot overwrite a more specific inner outcome.
- Session summaries count process non-zero, tool rejections, and internal errors separately; only internal tool errors contribute to connector-error counts.
- Activity disclosure renders the new taxonomy without exposing raw args/results.
- Background completion reminders use the unread-exec projection above and remain same-conversation only.

### 6. Goal / large-chat / reload hardening — SUPERSEDED / ALREADY_PORTED

The fork already contains stronger 2.1.x equivalents: scoped recovery state, exact navigation/conversation binding, one-pass ChatGPT turn walking for repeated capture decisions, durable Goal state, and explicit active-turn/live-generation guards. Do not replay upstream's older broad patch. Keep/extend regressions only where an invariant lacks direct coverage.

### 7. Agent-tab recovery / session cursor hardening — SUPERSEDED

Agent System 3.0 and the current worker lifecycle already provide stronger behavior: durable sleeping workers, exact conversation binding, bounded worker-tab lifecycle/five-tab budget, revival through existing chats, and caller-scoped durable histories. Do not replace these with the older upstream worker lifecycle.

### 8. Native macOS Desktop backend — REJECT FOR THIS INTEGRATION

The current fork architecture deliberately keeps Desktop/computer-use live discovery Windows-only. Enabling upstream's macOS backend would change a protected capability boundary rather than merely harden it. The portable browser-chord classifier may be ported, but no macOS Desktop surface, native helper, permission path, or packaging payload is added here.

## Validation

Each production slice gets RED -> GREEN focused verification, followed by adjacent suites. Final acceptance requires:

- `npm run verify:privacy`
- `npm run verify`
- `npm run build`
- `git diff --check origin/main..HEAD`
- no version-file changes
- no deletions/replacements under `src/main/orchestration/**`, Control Center, execution/managed-browser, updater, worker lifecycle, or protected recovery code
- Desktop live discovery remains Windows-only

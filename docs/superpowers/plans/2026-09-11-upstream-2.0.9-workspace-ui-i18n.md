# Upstream 2.0.9 Workspace UI / i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Simplified Chinese, useful project/transcript controls, the connector-refresh reminder and bounded presentation improvements from upstream 2.0.9 into the current 2.2.0 workspace without restoring older duplicate panes.

**Architecture:** English remains source copy. A small renderer-only i18n binder translates only app-authored UI and never rewrites provider/user content. Local Projects are durable organizational/workspace metadata layered on approved roots; selecting a project grants no filesystem authority. The existing 2.2.0 shell (`main-app.ts`), Chat workspace, Plugins workspace, Control Center, Fleet/Devices, Core Health and model/browser controls remain layout owners. Connector refresh is an informational per-version notice only.

**Tech Stack:** Electron renderer, TypeScript, DOM, preload IPC, durable JSON, Zod, Vitest/jsdom.

**Spec:** `docs/superpowers/specs/2026-09-11-upstream-2.0.9-selective-port-design.md`

## Global Constraints

- Translate only app-authored strings. User messages, assistant transcript, tool output, paths, plugin-provided names/descriptions and errors stay verbatim unless the app itself generated the label.
- English is canonical; `zh-CN` is the only new locale in this port.
- A language change must not overwrite a field/label another async UI update changed after the binding was installed.
- Local Project path must already resolve inside an approved root. Project selection cannot widen roots or bypass `sandbox.ts`.
- Removing a project means “remove grouping”; it does not delete files, sessions, input receipts or conversation history.
- Do not restore upstream duplicate context, agent, setup, model or plugin panes.
- Keep provider-usage/cost heuristics excluded.
- No version bump or release publication.

### Task 3: Add bounded backward/forward transcript history navigation

**Files:**

- Create: `test/renderer-timeline.test.ts`
- Test: `test/session-list-refresh.test.ts`

**Interfaces:**
- `ReadOptions.before?: number` means “return the bounded page immediately before this sequence number”. It is mutually exclusive with `from`.
- `sessions:events` accepts `{id, from?, before?, limit?}` through Core and Electron IPC.
- Renderer keeps `historyBefore`, `historyLoading` and selected-session/load-generation fences.

- [ ] **Step 1: Write store RED tests for bounded `before` paging**

Cover: newest default tail remains unchanged; `before=N` returns the previous bounded logical page in chronological presentation order; canonical message revisions do not duplicate or skip across a page boundary; `from` + `before` is rejected; corrupt/oversized historical rows retain existing bounded-read behavior.

- [ ] **Step 2: Add Core/UI IPC RED tests**

`session-events` must validate `before` as an integer sequence cursor, forward exactly one of `from`/`before`, and return `nextFrom` for forward paging. The Electron presentation process remains only a validated proxy to Core authority.

- [ ] **Step 3: Implement store/Core/preload support**

Adapt only the upstream `before` read semantics needed by the viewer. Do not add a second transcript store or materialize the entire journal to answer one bounded historical page when the existing reverse/tail machinery can be reused safely.

- [ ] **Step 4: Add renderer RED navigation tests**

Port/adapt the upstream behaviors: scroll/wheel/PageUp near the top requests an older page; scrolling/PageDown near the bottom of a historical window requests newer rows; “Back to latest” returns to the live tail; live `session:changed` refresh does not evict a historical window; changing selected chat while an older/newer request is in flight discards the stale result; prepending rows preserves the visible logical row rather than jumping the reader.

- [ ] **Step 5: Implement history window state in current `chat.ts`**

Keep the existing 160-row and text budgets. Use the current selection/load generations. When reading history, suppress ordinary live-tail delta replacement until the user reaches latest again. Show a compact “Back to latest” control only while off-tail.

- [ ] **Step 6: GREEN and commit**

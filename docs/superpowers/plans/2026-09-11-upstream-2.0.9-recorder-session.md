# Upstream 2.0.9 Recorder / Session Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port only the recorder/session correctness and latency improvements from upstream 2.0.9 that are still absent from fork 2.2.0, while preserving the fork's newer canonical message shards, durable catalog, execution state and privacy boundaries.

**Architecture:** The current session store stays authoritative. Exact request correlation is admitted independently of heavy transcript recording; proven calls serialize only within their request and destination session, so one attribution wait cannot stall unrelated chats. Canonical messages retain stable logical identity across revisions/reloads; late final evidence may repair a false-open turn only when durable ordering proves there was no newer work. Titles and prompts are derived through bounded pure helpers. No migration back to upstream's older session layout is allowed.

**Tech Stack:** TypeScript, Node fs, durable JSON/session store, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-11-upstream-2.0.9-selective-port-design.md`

## Global Constraints

- Keep current `messages/*.json` canonical message shards and the current session catalog. Do not reintroduce legacy append-only message ownership.
- Keep current `session` MCP tool and durable execution actions unchanged except where exact session principal from the coding-runtime plan is consumed.
- Recording failure is observability degradation, never authorization to fail an otherwise successful local tool.
- Exact request identity is first-proof-wins. Repair may move an unattributed historical record only when durable correlation proves its owner.
- Never use creation timestamp alone as message revision order; canonical sequence/origin is authority.
- Bound all scans, repair caches, disk reads, prompt/title text and benchmark outputs.
- No version bump/release publication.

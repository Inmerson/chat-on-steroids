# Post-2.1.2 Upstream Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the remaining compatible upstream hardening to fork v2.1.2 while preserving every protected 2.1.x subsystem and the Windows-only Desktop boundary.

**Architecture:** Re-derive five missing invariants on top of `origin/main` instead of merging upstream history. Each production change starts with a regression that fails on the fork baseline, then receives the smallest fork-native implementation and adjacent-boundary verification.

**Tech Stack:** Electron, TypeScript, MV3 JavaScript, Vitest, Node.js 22+, Git worktrees.

**Spec:** `docs/superpowers/specs/2026-09-05-post-2.1.2-upstream-hardening-design.md`

## Global Constraints

- Protected fork reference is `origin/main` / v2.1.2.
- No wholesale upstream merge, rebase, reset, force-push, or blind cherry-pick.
- Preserve Agent System 3.0, Control Center, autonomous execution, managed browser execution, Infinite Loop/scoped recovery, worker lifecycle/five-tab budget, authenticated terminal continuation, updater/release channel, privacy, permissions and sandbox invariants.
- Desktop remains live/discoverable only on Windows.
- Production behavior follows RED -> GREEN TDD.
- Do not change version values in `package.json`, `src/main/version.ts`, or `extension/manifest.json`.
- Final acceptance requires `npm run verify`, `npm run build`, `git diff --check`, and a protected-feature diff audit.

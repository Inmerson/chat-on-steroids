# Upstream 2.0.9 Windows Computer Use Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port upstream 2.0.9's Codex-style Windows desktop identity, capture, accessibility, keyboard and input improvements into the fork's existing `observe` / `computer` Desktop contract.

**Architecture:** Preserve the current two native Desktop tools, `observe` and `computer`. Extend `src/main/computer/*` with exact Windows app/window identity and richer native operations, then project those capabilities through backward-compatible additions to those two tools. When the coding-runtime plan is integrated, Desktop may additionally advertise the synthetic Code Mode `exec` composition tool; the thirteen Window2 methods stay internal to its Windows `sky` facade and never become thirteen new top-level MCP tools. Caller-scoped observation authority, frame generations, app identity and popup ownership remain the gates for stateful input.

**Tech Stack:** Electron, TypeScript, Windows PowerShell 5.1 helper, C#/Win32/UI Automation, Windows.Graphics.Capture, Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-11-upstream-2.0.9-selective-port-design.md`

## Global Constraints

- Windows-only. `desktopAutomationSupported()` remains `platform === 'win32'`; do not port upstream macOS Desktop automation.
- Keep direct Desktop tools exactly `observe` and `computer` unless a later approved spec changes the discovery architecture.
- Existing browser tab/window/history chord refusals remain fail-closed.
- Coordinate input requires a retained screenshot frame. Indexed semantic input requires a retained UI snapshot/ref. Exact app/window identity must be revalidated immediately before native input.
- A native mutation consumes observation authority even when the operation reports failure; callers must observe again before retrying ambiguous input.
- No shell-interpreted app launch arguments. Installed app discovery/launch uses native Shell identity or an exact executable with no arguments.
- No sleeps as race fixes; use helper generations, exact HWND/app identity, capture geometry and serialized input.
- No version bump or release publication in this plan.

# Upstream 2.0.9 Browser / Bridge Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the missing upstream 2.0.9 browser evidence, native-send receipt, observation-journal, Compact & Resume and idle-tab reliability improvements into the fork's current extension/bridge architecture without regressing Agent System 3.0 or durable execution rollover.

**Architecture:** Treat the extension as observation/routing evidence only. Exact request identity comes from a bounded MAIN-world response observer plus existing Fiber evidence; neither source gains tool authority. The service worker keeps custody of accepted browser observations/receipts across MV3 suspension, with per-conversation fairness. Bridge changes are admitted only when the current 2.2.0 code lacks the exact behavior; current execution-rollover, worker placement, blocked-chat and persistent-Core state machines remain authoritative.

**Tech Stack:** Chrome MV3 JavaScript, Electron/TypeScript bridge, durable session store, Vitest/jsdom test harnesses.

**Spec:** `docs/superpowers/specs/2026-09-11-upstream-2.0.9-selective-port-design.md`

## Global Constraints

- Do not copy `extension/content.js`, `background.js`, or `src/main/bridge.ts` wholesale from upstream.
- Preserve bridge protocol 10 unless a wire shape actually changes. If it must change, update app+extension atomically and add compatibility tests before bumping it.
- Every page-derived identity is scoped by conversation + document/navigation epoch; stale A→B→A observations must not survive.
- No request headers, cookies, credentials, prompt bodies or tool arguments may cross from MAIN-world request observation. Only exact `conversation_id`, normalized `metadata.request_id`, timestamp and bounded quota rows are permitted.
- A browser send/Stop/open attempt is authorized exactly once by the current app-side durable command/input claim; ambiguous delivery is never silently replayed to another tab.
- Current 2.2.0 execution rollover and Agent System 3.0 worker lifecycle win over upstream older equivalents when semantics overlap.
- No version bump or release publication in this plan.

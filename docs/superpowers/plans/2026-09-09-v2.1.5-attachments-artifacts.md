# Chat On Steroids 2.1.5 Attachments and Artifacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add upstream file/image input and artifact fetch/download support to the fork's durable session and sandbox model.

**Architecture:** Attachment identity is stored with the durable session, binary material remains bounded under session assets or explicitly approved destinations, and all host-path resolution uses existing sandbox/root checks. Remote device paths remain opaque to the local filesystem layer. Artifact downloads validate destination and overwrite policy before mutation.

**Tech Stack:** TypeScript, Node filesystem, Electron IPC, MCP, Chrome extension, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-09-upstream-feature-port-v2.1.5-design.md`

## Global Constraints

- No attachment broadens approved roots or `allComputer` authority.
- Local path resolvers must never interpret a remote `device_id` path as a local host path.
- Existing session recorder/store remains source of truth.
- Version stays 2.1.4 until release integration.

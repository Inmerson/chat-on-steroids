# Chat On Steroids 2.1.5 Plugins Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the upstream Plugins workspace, plugin lifecycle, MCP exposure and compliance assets onto the 2.1.4 persistent-Core architecture without widening permissions or bypassing multi-device boundaries.

**Architecture:** Plugin authority lives in Core Host. Electron renderer/preload only proxies fixed IPC operations; plugin secrets use the existing secure-storage boundary; model-visible plugin tools are exposed through an explicit Plugins MCP surface rather than silently expanding Core. Upstream `origin/main` is the behavioral source, but fork Core, capability and updater semantics remain authoritative.

**Tech Stack:** Electron, TypeScript, MCP SDK, Zod, Vitest, Chrome/Electron renderer, OS secure storage.

**Spec:** `docs/superpowers/specs/2026-09-09-upstream-feature-port-v2.1.5-design.md`

## Global Constraints

- Preserve persistent Core Host/supervisor, Agent System 3.0, Control Center, autonomous execution, Infinite Loop, worker five-tab budget and multi-device routing.
- Plugin install/enable/authentication is always an explicit user action.
- Plugin secrets are never persisted in plain `config.json`.
- Plugins receive no implicit `device_id` or remote execution authority.
- Do not replace `src/main/core/**`, `src/main/orchestration/**`, `src/main/multidevice/**`, or the fork updater.
- Keep version values at 2.1.4 until the final release plan.

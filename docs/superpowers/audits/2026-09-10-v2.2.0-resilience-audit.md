# Chat On Steroids 2.2.0 Runtime Resilience Audit

Baseline: `58590d8f35d3cd83e01e7001b2c6b8e15168e24f`.

This audit consolidates the historical recovery/lifecycle and platform-hardening plans into one execution tranche. Each candidate is classified against the current fork before production edits. Protected fork architecture remains authoritative: persistent Core, Manager/Control Center, Agent System 3.0, Infinite Loop/scoped recovery, five-tab lifecycle, exact conversation binding, multi-device routing, authenticated terminal continuation, sandbox/capabilities and updater lineage.

## Recovery and lifecycle

- `374dabf` destination-loss relay — **SAFE_MANUAL_PORT**. Current `extension/background.js` has no `destinationLost` relay or centralized checkpoint allowlist, while current continuation/bridge logic already consumes the surrounding checkpoint contract. Port only the missing allowlisted field/relay shape; do not replace continuation state.
- `554c4bb` every-session correctness — **SAFE_MANUAL_PORT**. Current correctness callers in `session-tool.ts`, `correlation.ts` and `recorder.ts` still use bounded `listAllSessions()` even though `store.ts` already has uncapped `readEverySummary()`. Export and use the uncapped catalog only for the three correctness promises.
- Project conversation routes — **ALREADY_PORTED**. Current extension/session tests already recognize Project conversation URLs and preserve exact conversation identity. No production edit.
- `f3c1741` blocked-chat custody, refined by `0f50778` — **SAFE_MANUAL_PORT, bounded subset**. Current fork has no durable blocked-chat registry. Port exact-conversation durable blocking and MCP refusal only; integrate via existing session IPC/list UI rather than replacing fork recovery or renderer architecture.
- Desktop helper generation provenance (`07d4196`) — **ALREADY_PORTED**. Current `computer-generation`, stale-ref/frame and helper-retirement suites cover generation provenance. No production edit.
- `2c6967a` tunnel single-owner restart — **SAFE_MANUAL_PORT**. Current tunnel supervisor can schedule a replacement after a stop attempt without proving the previous tree retired. Port single-owner retirement/CAS semantics without changing Core tunnel ownership.
- `76b169e` readiness confirmation — **SAFE_MANUAL_PORT**. Current watcher replaces the tunnel after one failed `/readyz`; port a bounded second-pass confirmation.

## Platform hardening

- `6b2c23d` multilingual access-limit verdict — **SAFE_MANUAL_PORT**. Current content classifier can identify blocking dialogs, but the `blocking` verdict is not carried through observation parsing to recovery policy.
- `10c25aa` RTL answer rendering — **SAFE_MANUAL_PORT**. Current renderer has no bounded `dir` preservation/`dir=auto` handling for recorded message content.
- Windows `uv` discovery + modern MCP JSON (`53d5aaa`) — **ALREADY_PORTED**. Current plugin installer/environment tests cover standard `uv` discovery and current MCP tests accept modern/legacy envelopes.
- Windows swapped mouse buttons (`87a9d9b`) — **ALREADY_PORTED**. `SM_SWAPBUTTON` handling exists and the dedicated test suite is GREEN.
- Brave browser support (`335cb29`) — **ALREADY_PORTED in Task 1**. Chrome/Edge/Brave selection and candidate tests are GREEN. Readiness half is handled with the tunnel port above.
- Linux DEB teardown determinism (`bfd8c98`) — **TEST/RUNTIME PORT**. Current release workflow still uses raw `trap 'rm -rf ...' EXIT`; use the existing AppImage principle that cleanup cannot override product smoke evidence.

## Rejected scope

- No wholesale cherry-pick of upstream bridge/session/agents/renderer/tunnel files.
- No upstream Goal/exec-custody/repair-protocol rewrite from the broad `0f50778` commit.
- No weakening or deletion of protected fork recovery/orchestration tests.
- No version bump, public push, tag, release or installation in this tranche.

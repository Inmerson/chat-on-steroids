# ChatGPT Local Files v1.6.0 — live smoke test + code audit

Date: 2026-08-16
Tester: prime ChatGPT session + exactly one worker agent (`Code audit`)
Repo: `/totec/chatgpt-local-files`
Installed build: v1.6.0

## Executive summary

v1.6.0 is a substantial UI improvement over the broken Chat panel seen before 1.6. The desktop app is usable at the default window size, the long Timeline renders correctly, the empty Compaction view renders correctly, expanded tool calls open inline instead of being welded to the side, and sensitive `agent_key` values are redacted in the desktop timeline. The main/prime ChatGPT tab also successfully receives extension relabeling: tool rows show real names, agent pills and timestamps.

However, this is **not ready to call fully hardened**. The biggest live extension failure is still reproducible in the worker chat: its grouped connector row remains generic `Called tool`, has no extension `+N` grouping UI, and the native expanded card showed a `Search files` request paired with an `agent_status`-looking response. That is direct evidence that the one-visible-row-to-local-call mapping is not trustworthy in this shape. The worker audit also confirmed multiple open multi-agent lifecycle bugs which existing tests do not cover.

`npm run verify` was run by the worker against the current v1.6.0 tree and passed: typecheck + 18 test files, **534 passed / 1 skipped**. The green suite therefore does not mean the lifecycle/grouping cases below are safe; several are explicitly missing regression coverage or have fixtures that encode the flawed assumption.

## Live UI / UX findings

### P1 — direct window targeting is unreliable

Both of these failed while `ChatGPT Local Files` was listed as an open window (`id 460384`) but Chrome was foreground:

- `screenshot(window=460384)` -> `FOCUS_FAILED: requested 460384 but foreground is 67036`
- `computer.focus(window=460384)` -> same `FOCUS_FAILED`

Using normal `Alt+Tab` brought the app foreground, after which `screenshot(window=460384)` worked immediately. A window-targeted screenshot should either capture a non-foreground window or the focus action should be able to foreground a listed open window. Right now model-side automation has to fall back to keyboard navigation.

### P2 — Activity health semantics conflict

Home `Run checks` reported **Every check passed**, while the app simultaneously displayed a red `1 problem` badge. The problem was:

`join_agent accepted worker-1 from its sole browser bootstrap without fresh page evidence`

If that is an actual safety warning, the all-green health state is misleading. If it is expected during a successful bootstrap, it probably should not be counted as a red problem. Either way the two surfaces currently disagree.

A desktop drag action produced a plain `Unknown event` entry in the prime Timeline. The action itself was real and recorded, but the renderer has no meaningful presentation for it. This makes the session log look partially broken even when the action succeeded.

### P2 — finished-worker Activity filtering disappears

While the worker was active, Activity exposed agent filters including `Prime` and `Code audit`. After the worker finished, those per-agent filters disappeared from Activity, leaving only `All / Problems`. Historical worker activity should remain filterable after completion.

### P3 — `Show less` is jammed against message text

The desktop Timeline user-message card rendered the end of the user text as:

There is no visible spacing/separation before the `Show less` control. Minor, but obvious polish issue.

### P3 — `Disconnect browser` does not look like a control

In Chat Settings -> Chrome Extension, `Open extension folder` is visibly a button, while `Disconnect browser` appears like low-contrast helper text on the same line. It is an action and should have button/link affordance comparable to the rest of the UI.

### P3 — old unattributed activity remains visually noisy

The Chat picker still contains an `Unattributed activity` recording with `0 messages · 487 tools` and a full red progress bar. Even if this is historical data rather than a new v1.6 regression, it remains a large, alarming item in the primary session list and reinforces T-40/T-41 cleanup needs.

## Code-audit findings from worker

The worker made **no code edits** and ran the full verification suite successfully. It confirmed the following issues in source.

### P0/P1 — multi-agent lifecycle/correctness

1. **Lost first `join_agent` result can leave an active zombie worker.**
   `joinBootstrappedAgent()` clears bootstrap state and activates the worker before returning the key. A retry through `joinFromBootstrap()` with zero candidates only throws `already joined; keep using key`; it does not use the existing `joinBoundConversation()` recovery path. If the first result/key is lost, the worker can be active but unrecoverable. This is the core of T-29.

2. **Cold MV3 background load race can lose observations.**
   `extension/background.js` uses a boolean `loaded` rather than a singleflight `loadPromise`. Concurrent first messages can both read old storage; a slower load can overwrite globals after another handler has already enqueued/persisted new journal data.

3. **Bridge command overflow corrupts lifecycle cleanup.**
   The overflow path still uses raw `commands.shift()` instead of the lifecycle-aware `drop()` path. A dropped worker/resume command can leave the worker invited or resume job busy. T-33 confirmed.

4. **Closing one duplicate tab can close the whole conversation session.**
   `pagehide -> HANDLERS.closed -> /closed` is conversation-wide with no tab refcount. If two tabs show the same conversation, closing one can mark the session closed while the other is still open.

5. **Worker recovery can still open duplicate tabs.**
   A sent worker command remains leased awaiting join. After lease expiry, delivery can open another marked tab even when the bridge already knows a live/bound conversation id. T-27 remains real.

6. **`createAgents()` is non-transactional.**
   Worker task validation happens inside the mutation loop. A blank later task can leave prime and earlier workers already created. Pre-validate the whole request first. T-31 confirmed.

7. **`finishAgent()` is non-idempotent and terminal sender semantics are loose.**
   Retrying finish rewrites `finishedAt`/result and can queue another final report. Finished-agent credentials remain usable and `sendMessage()` does not reject a terminal sender. T-32/T-60 confirmed.

8. **Agent messages are recorded but omitted from compaction.**
   The recorder has `agent_message` events, but `compact.ts packSession()` has no case for them, so the prime can Compact & Resume and silently lose delivered worker findings. T-34 is high impact because worker reports are exactly what the resumed prime needs.

### P1/P2 — extension / attribution / browser bridge

9. **Unnecessary raw `args` + first 4k of `result` are sent to every ChatGPT content script** by `/activity`, even though current page painting does not need them. This is needless exposure and payload.

10. **Disconnect state is not fully respected by the Compact UI.**
    Background status exposes `disconnected`, but content `checkStatus()` keeps only connected/paired state and compaction controls gate on `connected`. After deliberate Disconnect, Compact & resume can still look enabled and only fail after click.

11. **Page-label style can leak after authoritative relabel.**
    `applyPageLabel()` adds `.clf-page` / `dataset.clfPage`; the later authoritative `applyLabel()` path does not remove them, so a row can remain in the page-sourced italic/0.8-opacity style after the recorder has taken ownership.

12. **Folded-call model is overconfident.**
    `planLabels()` treats ChatGPT's `collapsedSameToolCallCount` as a reliable count/order of local recorded calls immediately before the representative row. Live evidence from this test directly supports the concern: the worker's one generic grouped row expanded to a `Search files` request with a response shaped like another call. Keep `+N` as page information, but only assign identities to hidden local calls when ordering/identity is proven.

13. **`/pair` token rotation can make multiple extension clients revoke each other.**
    Background singleflight only protects one service worker. Multiple profiles/extensions pairing against the same app can rotate the server token out from under one another. Pairing should be idempotent to an existing client or use per-client tokens.

14. **Command polling is still duplicated per tab / stale close liveness remains.**
    Each content tab polls through background, and background has no singleton for `/commands`. Also `/closed` leaves `conversationSeen` live until TTL (T-41). Lower severity individually, but they add noise and make lifecycle reasoning harder.

## Suggested fix order

1. **Fix lost join-result recovery first.** A worker that becomes active without a recoverable key is the worst possible state because the app thinks it succeeded.
2. **Fix `agent_message` compaction omission before relying on Compact & Resume for multi-agent work.** Today the most important worker output can disappear from the handoff.
3. **Make lifecycle mutations idempotent/transactional:** `createAgents`, `finishAgent`, queue-drop handling.
4. **Fix worker/grouped-row labeling based on live evidence, not fixtures.** The prime path works; the worker grouped-row path does not. Do not generalize from the working prime chat.
5. **Fix duplicate-tab/conversation close and reopen behavior** before claiming the tab-storm class closed.
6. **Make diagnostic surfaces agree.** `Every check passed` and a red join safety problem cannot both be the primary truth without explanation.
7. Then do the smaller polish items: Activity finished-agent filters, `Unknown event`, `Show less` spacing, Disconnect affordance.

**v1.6.0 is meaningfully better and the desktop Chat P0 layout repair is visually successful.** The app is usable enough to continue development and the prime-chat extension presentation is finally doing what it was meant to do. Keep v1.6 in active hardening rather than treating the connector as finished.

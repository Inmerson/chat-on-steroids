Chat On Steroids 2.1.4 introduces the first release-ready multi-computer coordinator path and a
reworked desktop workspace for viewing local Core state, managed computers, pairing, and agent
orchestration from one place. The app and companion extension are versioned together, so **reload
the browser extension after updating the app**.

## 2.1.4

### Multi-computer coordinator

- Core now has a durable managed-device registry with a local coordinator identity and remote
  device summaries. Pairing uses one-time codes that expire after 10 minutes.
- Successful enrollment receives a resume credential for later authenticated reconnects. Stored
  pairing and resume secrets are retained only as digests, and revocation removes the saved resume
  credential for that device.
- Coordinator transport tracks remote online/offline presence and routes an explicit request to the
  exact enrolled device rather than silently falling back to another computer.

### Remote tool routing

- `read`, `apply_patch`, and `exec_command` can target an explicit managed `device_id`; omitting it
  preserves the existing local-computer path.
- Remote reads are deliberately limited to one concrete path, remote patches require an explicit
  patch payload, and remote command execution is non-interactive.
- Device routing remains subject to the same Chat On Steroids capability checks before an operation
  can leave Core.

### Desktop workspace

- The desktop home view now exposes coordinator status, approved workspace context, managed-device
  inventory, and a pairing-code flow without inventing remote state that Core has not reported.
- Navigation is consolidated into a left workspace rail with direct connection and system-check
  controls. The Control view receives a denser orchestration canvas while keeping Core as the source
  of truth for task state.
- Structured Core health information is shown through the main renderer state, keeping health,
  connection, and device presentation synchronized.

### Verification scope

- 2.1.4 adds focused tests for the device registry, coordinator transport, remote MCP routing, Core
  IPC/dispatch integration, renderer layout, and lightweight Core helper behavior.
- Release metadata is checked against `package.json`, `package-lock.json`, the companion extension,
  `APP_VERSION`, this release note, and the published artifact matrix before release jobs run.

> Beta despite the version number. Behaviour may still change between releases.

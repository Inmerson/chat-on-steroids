Chat On Steroids 2.1.2 is a selective upstream-synchronization and reliability patch for the 2.1
autonomous-execution line. The app and standalone companion extension are versioned together, so
**reload the browser extension after updating the app**.

Choose the artifact for your operating system and CPU:

- `Chat-On-Steroids-Setup-x64.exe` — Windows x64 (Intel/AMD)
- `Chat-On-Steroids-Setup-arm64.exe` — Windows on Arm
- `Chat-On-Steroids-macOS-x64.dmg` — macOS Intel disk image
- `Chat-On-Steroids-macOS-x64.zip` — macOS Intel app archive
- `Chat-On-Steroids-macOS-arm64.dmg` — macOS Apple silicon disk image
- `Chat-On-Steroids-macOS-arm64.zip` — macOS Apple silicon app archive

## 2.1.2

### Reliability and compatibility

- Worker command tabs remain open after bootstrap acknowledgement and are released only by the
  dedicated agent-tab lifecycle after durable sleeping/terminal evidence. This keeps the browser
  document alive while identity-sensitive MCP calls may still need exact request-id-to-conversation
  attribution.
- Desktop automation now binds replies to the exact helper-process generation that issued the
  request. A reply arriving after helper replacement is rejected instead of being allowed to carry
  stale frame, ref, or window-state evidence into the new generation.
- Bridge shutdown coverage now waits for the server to accept the in-flight request before testing
  drain behavior. This is a test determinism improvement; the production bridge protocol remains
  unchanged at protocol generation 10.

### UI and activity visibility

- App-owned tool activity rows can be expanded with native `<details>` disclosures. The panel is
  keyboard-operable and limited to bounded metadata such as tool name, outcome, duration, and a
  capped set of changed paths/counts.
- Tool disclosures deliberately exclude raw tool arguments, results, credentials, and arbitrary
  nested payloads.
- Folder access stays reachable after setup through the existing settings flow, without widening
  approved roots or granting any new filesystem permission automatically.

### Upstream provenance and release validation

- Historical original-repository notes for upstream 2.0.3, 2.0.4, and 2.0.5 are restored for
  lineage/provenance. They are explicitly marked as upstream history, not as Inmerson release tags.
- The 2.1 fork remains selective rather than wholesale-synchronized: Agent System 3.0, Control
  Center, autonomous execution, Infinite Loop/scoped recovery, worker lifecycle, and the fork
  updater/release channel are preserved.
- The static AppImage launcher assertion loads `app-builder-lib` during suite setup rather than
  inside the individual 30-second test timeout, removing a full-suite-only validation flake without
  changing packaged AppImage behavior or the assertions themselves.

> Beta despite the version number. Behaviour may still change between releases.

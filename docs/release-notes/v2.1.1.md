Chat On Steroids 2.1.1 is a reliability and distribution patch for the 2.1 autonomous-execution
line. The app and standalone companion extension are versioned together, so **reload the browser
extension after updating the app**.

Choose the artifact for your operating system and CPU:

- `Chat-On-Steroids-Setup-x64.exe` — Windows x64 (Intel/AMD)
- `Chat-On-Steroids-Setup-arm64.exe` — Windows on Arm
- `Chat-On-Steroids-macOS-x64.dmg` — macOS Intel disk image
- `Chat-On-Steroids-macOS-x64.zip` — macOS Intel app archive
- `Chat-On-Steroids-macOS-arm64.dmg` — macOS Apple silicon disk image
- `Chat-On-Steroids-macOS-arm64.zip` — macOS Apple silicon app archive
- `Chat-On-Steroids-Linux-x64.AppImage` — Linux x64 portable AppImage
- `Chat-On-Steroids-Linux-x64.deb` — Linux x64 Debian/Ubuntu package
- `Chat-On-Steroids-Linux-arm64.AppImage` — Linux ARM64 portable AppImage
- `Chat-On-Steroids-Linux-arm64.deb` — Linux ARM64 Debian/Ubuntu package
- `Chat-On-Steroids-Extension.zip` — standalone Chrome companion extension
- `SHA256SUMS.txt` — SHA-256 checksums for every release artifact above

> **macOS caveat:** the DMG and ZIP builds are currently **publisher-unsigned (no Apple Developer
> ID) and unnotarized**. Apple-silicon Mach-O executables may still carry platform-required ad-hoc
> signatures, but those do not establish publisher identity or Gatekeeper trust. The macOS builds
> require **macOS 13 Ventura or newer**.

## 2.1.1

### Updates and packaging

- Packaged Windows installs and Linux AppImages can stage a newer release in the background,
  verify it against the release SHA-256 manifest, and install it only when the user presses
  **Install**. The staged artifact survives an app restart so it is not downloaded twice.
- Debian packages remain owned by the system package manager, and unsigned/unnotarized macOS builds
  remain manual-update surfaces. Those installations are notified and linked to the release page.
- The updater and standalone extension recovery both follow `Inmerson/chat-on-steroids` release
  assets, so fork-only versions resolve to the matching app/extension pair.
- OpenAI `tunnel-client` is updated to **v0.0.14** with per-platform checksums. Publish preflight
  verifies that the pinned tunnel-client is still OpenAI's current stable release.
- macOS packages now declare **macOS 13 Ventura** as their minimum supported system, matching the
  native tunnel-client payload that ships inside the app.
- Windows installer/update runs repair the Electron sandbox read/execute ACL on the installed app
  tree without disabling Chromium's sandbox.

### Session and file-tool reliability

- Session pagination/update cursors are compact checksum-bound tokens instead of long base64 JSON.
  A damaged copy or a cursor from another recording is rejected with a specific recovery message.
- `read` accepts a line range attached to one path (`path:12-40` or `path:12`), so several ranges
  from one file can be requested in one call while call-wide `start_line` / `end_line` still work.
- A missing read path now includes the nearest existing folder listing when directory browsing is
  permitted, removing the extra discovery call normally needed after a mistyped path.

### UI

- Update status is part of the normal app-state projection. A verified staged update exposes an
  **Install** action; installations that cannot self-replace get a manual release link instead.
- The update notice integrates with the existing shell layout rather than adding a competing modal
  or interrupting autonomous work.

> Beta despite the version number. Behaviour may still change between releases.
